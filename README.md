# S/V Oroboro — sailingoroboro.com

The sailing journal of Francesco and Yuka — two former Silicon Valley tech workers who quit their jobs in 2018 to sail around the world on a Leopard 40 catamaran named Oroboro. Seven years and 25,000 nautical miles later, they're still out there.

**Route:** Cape Town → Namibia → South Atlantic → St Helena → Brazil → Caribbean → Bahamas → Azores → Portugal → Mediterranean → Greece (ongoing)

## Adding a New Post (full workflow)

This is the answer to the oldest open question in the blog vault.

### Step 1 — Write the post

Create `content/<slug>.md` with YAML frontmatter:

```markdown
---
title: Your Post Title
slug: your-post-slug
date: 2021-08-10          # EVENT date — controls sort order in the voyage log
published: 2026-07-20     # actual publication date — shown as "published July 2026"
region: Europe            # see MARKDOWN_REGION_MAP in build.py for valid values
categories: [Sailing, Europe]
lat: 38.72                # for map integration
lon: -9.14
hero: portugal/lisbon-harbor.jpg   # R2 key for the hero/card image (uploaded in step 2)
---

Write your post in standard markdown here.

Images: ![Caption text](portugal/photo.jpg)
— path is the R2 key under your prefix; upload_images.py handles the upload.

Place image placeholder comments where photos will go:
<!-- IMG: description of what should go here -->
```

**Ordering:** `date:` is the event date — the post slots into the voyage log chronologically regardless of when you write it. If a legacy WordPress post also needs its sort date corrected, add it to `SORT_DATE_OVERRIDES` in `build.py`.

**Valid region values** (from `MARKDOWN_REGION_MAP` in build.py):
`Azores`, `North Atlantic`, `Atlantic`, `Europe`, `Mediterranean`, `Portugal`, `Sailing`, `Boat`, `Technology`, `Caribbean`, `Brazil`

### Step 2 — Upload photos to R2

Install dependencies once if needed:

```bash
/usr/bin/pip3 install -r requirements.txt
```

Set R2 credentials (get them from Cloudflare dashboard → R2 → Manage R2 API Tokens → Create API Token with Object Read & Write):

```bash
export R2_ACCOUNT_ID=your_account_id
export R2_ACCESS_KEY_ID=your_access_key
export R2_SECRET_ACCESS_KEY=your_secret_key
```

Resize and upload a folder of chosen photos:

```bash
/usr/bin/python3 upload_images.py ~/Desktop/my-photos portugal
```

This resizes each photo to max 1600px JPEG quality 85 and uploads to R2 under the `portugal/` prefix. The script prints ready-to-paste markdown image tags.

Dry-run (resize only, no upload):

```bash
/usr/bin/python3 upload_images.py ~/Desktop/my-photos portugal --dry-run
```

### Step 3 — Fill in image placeholders

Replace each `<!-- IMG: ... -->` comment in the markdown file with the markdown from the upload script output:

```markdown
![Caption text](portugal/photo.jpg)
```

Set or confirm the `hero:` frontmatter field to the key of the best card image.

### Step 4 — Build and verify locally

```bash
/usr/bin/python3 build.py
```

Open `posts/<slug>.html` in a browser to check layout, dual dates, prev/next links.

Check `blog.html` to confirm the post appears in the correct chronological position.

### Step 5 — Update the map (if new coordinates)

Add the post to `POST_LOCS` in `gpx_to_mapjs.py`:

```python
("your-post-slug", "Location Name", lat, lon, "Mon YYYY", "region"),
```

Then regenerate the map:

```bash
/usr/bin/python3 gpx_to_mapjs.py
```

### Step 6 — Commit and deploy

```bash
git add content/<slug>.md posts/<slug>.html blog.html index.html js/map.js
git commit -m "Add post: <title>"
git push
```

GitHub Pages serves from the `main` branch root; the post is live within ~60 seconds.

## Regenerating All Pages

To rebuild all legacy + markdown posts from scratch:

```bash
/usr/bin/python3 build.py
```

**What build.py writes:**
- `index.html`, `blog.html`, `about.html`, `map.html`
- `posts/<slug>.html` for every legacy (WordPress XML) and markdown post

**What build.py never touches:**
- `links.html` — hand-authored Instagram link-in-bio page
- `posts/oroboro-dashboard.html`, `posts/boat-manager-app.html` — hand-authored tech posts
- Any file not in its explicit output list

**Pre-built tech posts** (`PREBUILT_POSTS` in build.py) appear in blog listings and index but their HTML is never regenerated. Update their metadata in `PREBUILT_POSTS` if titles/excerpts change.

## Rebuilding the Map

The map is generated separately from post content:

```bash
/usr/bin/python3 gpx_to_mapjs.py
```

Reads GPX tracks + `POST_LOCS` table → writes `js/map.js`. Run this when adding a new post with new coordinates, or when new GPX tracks are added.
